# Security Policy

## Supported Versions

This project is a static study-support website. Only the latest published version is supported.

| Version | Supported |
| ------- | --------- |
| v79 / latest published version | ✅ |
| Older versions | ❌ |

Older ZIP files and older GitHub Pages deployments are not maintained. If you are using an older version, please update to the latest published version.

## Scope

This project does not provide accounts, payments, server-side storage, or a backend API. The site runs in the browser as a static HTML/JavaScript application.

Security reports should focus on issues such as:

- Exposure of unintended private information
- Unexpected external network requests
- Malicious script injection or cross-site scripting
- Broken access/search-prevention settings such as missing `noindex`
- Download/package contents that include unintended files
- Other behavior that could harm users or the school community

The following are not treated as security vulnerabilities, but may still be reported as ordinary issues:

- Incorrect answer data
- Incorrect scoring or point allocation
- Broken source or explanation links
- Display bugs
- Browser compatibility issues

For incorrect answer data or ordinary bugs, please use the Google Form linked in the site.

## Reporting a Vulnerability

Please do not publicly post sensitive security details in GitHub Issues or other public places.

Report suspected vulnerabilities through the Google Form linked on the site:

https://forms.gle/C1fmLaa3vXEdaXPd7

When reporting, include as much of the following as possible:

- The version number shown on the site
- The page or feature affected
- Steps to reproduce the issue
- What you expected to happen
- What actually happened
- Screenshots, if helpful
- Whether the issue appears on GitHub Pages, Netlify, or both

## Response Policy

This is a non-commercial, unofficial study-support project. There is no formal security response team and no bug bounty program.

Reports will be reviewed when possible. If a report is accepted, the issue may be fixed in a later version. If the report is not considered a security vulnerability, it may be treated as an ordinary bug report.
